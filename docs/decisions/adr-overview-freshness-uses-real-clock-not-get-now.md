# Overview checked times and the failed sign-in window use the real clock, not `getNow()`

The project convention is that server code takes "now" from `getNow()` so the dev date picker and tests stay deterministic. Overview metrics report when a measurement was actually taken, and the failed sign-in count covers the 24 hours before that check. Overview therefore stamps `checkedAt` with the real clock (`new Date()` fallback in `src/lib/overview-readers.ts`, injectable through the `now` argument for tests), and the page calls `await connection()` so it is never statically rendered. A mocked date would make a probe look fresher or older than it is and would shift the sign-in window away from the real recorded events; the cost is that Overview ignores the dev date picker and tests inject `now` instead. Activity's `loadedAt` already follows the same rule. Sources: `story-overview-tracer-plan.md` (ticket 5.1, Design Notes), `story-recent-admin-actions-and-failed-logins-plan.md` (ticket 5.5), commit `84866562`. The plans state the choice but not an explicit trade-off discussion; the reasoning above is the retrospective's reading of the code comment and plans, not a quoted rationale.
