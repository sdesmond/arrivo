# Overview metrics refresh through per-metric server actions with no persistence

Each Overview metric must refresh independently, show Unavailable with Retry when its probe fails, and keep a stale value with its original timestamp. Rather than store readings in a cache table, each metric refreshes through its own server action in `src/app/(app)/admin/overview/actions.ts` returning `{status, value, checkedAt}` from the existing plain readers, and the client holds the last successful value and marks it Stale after a failed refresh. Each action rechecks admin authority before measuring, and authorization failures escape measurement error handling so a denied request is never shown as Unavailable. Nothing is persisted, so a reload shows a fresh measurement and no stale state survives it; the cost is that "last known good" lives only in the open page. Sources: epic Notes decision of 2026-10-30, `story-per-metric-refresh-retry-and-stale-states-plan.md` (ticket 5.6), commit `ba2fdb92`. The plan and epic Notes state the decision; the cost described above is inferred from the design, not quoted from them.
