# Admin deletion uses keyed, stateless outcome fingerprints

Admin deletion must demand renewed confirmation when trip succession changes without revealing private trip or successor identities. Preview and commit therefore use an HMAC of canonical per-trip outcomes, bound to target account and setup state; commit recomputes those outcomes under lifecycle locks and accepts only a matching fingerprint. The key prevents clients from testing guesses about hidden identifiers, while stateless review avoids persisting previews; changing canonicalization or key invalidates outstanding confirmations and requires renewed review. Source: `story-admin-deletion-and-private-succession-plan.md`, Design Notes, commit `0f785921`; implementation: `src/lib/account-deletion.ts`. Approved during epic 4 retrospective on 2026-10-30. This records intended privacy design; it does not resolve the retrospective's separate lifecycle findings.
