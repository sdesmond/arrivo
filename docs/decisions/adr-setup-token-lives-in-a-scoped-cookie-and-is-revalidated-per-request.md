# The setup token lives in a scoped HttpOnly cookie and is revalidated against the database on every request

A setup link must stop admitting anyone the moment it is replaced, expires or its account is deleted, and the setup-only browser context is deliberately not an Auth.js session. The cookie `arrivo_account_setup` therefore holds the raw token, is scoped to `Path=/account-setup`, and every request to the setup page, the exchange route and the setup server actions re-hashes it and checks it against `credential_authorizations`. The database is the only state, so replacement, expiry and deletion revoke the context on the next request with no cookie-side bookkeeping to clean up. The cost is a live credential held in the browser for up to the link's 24 hours, limited by `HttpOnly`, a `Max-Age` capped to the link's remaining lifetime, and the narrow path, so the token is not sent to routes that never read it. Source: `story-setup-only-context-tracer-plan.md` (Design Notes), commits `74683152` and `2bd701a9`, with the path narrowing in `74faed8b` after the late authority review.
