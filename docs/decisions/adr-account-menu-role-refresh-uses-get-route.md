# Account menu refreshes admin authority with a GET route, not a server action

The account menu must drop "Manage app" as soon as a demoted admin navigates, but Next.js keeps layouts across client navigation, so a layout prop alone goes stale. A server action for the refresh was tried first and reproduced a router-state rollback: with two role actions resolving around a Settings navigation, `/profile` was replaced by stale `/trips` state, because server actions queue behind each other in the router. The menu therefore reads authority from the authenticated `GET /api/users/me/app-role` (`Cache-Control: no-store`, client `cache: "no-store"`), keyed on pathname plus search parameters, which stays outside that queue; server-side `requireAdmin()` guards are unchanged and remain the real enforcement. Do not turn this back into a server action. Source: `story-account-menu-and-manage-app-shell-plan.md` (Implementation Notes, Plan Change Log), commit `d7aafcc`.
