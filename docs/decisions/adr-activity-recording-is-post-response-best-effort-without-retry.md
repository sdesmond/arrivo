# Activity is recorded after the response through `after()`, best-effort, with no retry or outbox

Activity must never change the outcome of the action it describes, including when storage fails. `recordActivity` therefore returns `void`, is called only after the primary mutation has committed (never inside its transaction), schedules the insert with Next's `after()`, bounds it with a five-second timeout, catches scheduling and persistence failures alike, and logs the error class only because driver messages can echo row values. There are no retries and no outbox, so an event lost to a failed write is gone for good; that loss is accepted in exchange for zero coupling to the primary path. Occurrence time comes from an injectable real clock, not `getNow()`, so simulated itinerary dates never decide batching or retention. Source: `story-sign-in-to-activity-tracer-plan.md` (Design Notes) and the epic's Build contracts, commit `35ae868`.
