- (direction) Sources: brainstorm-admin-page (scope), UX EXPERIENCE/DESIGN (behavior, adopted), architecture spine (binding semantics, adopted). Precedence: architecture > UX > brainstorm.
- (decision) Admin-created accounts replace email invitations: admin supplies username only; account exists immediately with no password; manual 24h setup link bound to account ID (UX overrides brainstorm email invitations; username decided).
- (capability) CAP-1 Bootstrap: first account becomes admin, signup closes permanently; sole legacy account auto-promoted on upgrade; multiple legacy accounts halt with operator error.
- (capability) CAP-2 Add User: admin creates passwordless account + setup link; mandatory non-dismissable password dialog; setup-only access until saved.
- (capability) CAP-3 Setup link lifecycle: resume until expiry, regenerate for same account, expired keeps account, delete before first login.
- (capability) CAP-4 Admin role: promote/demote, last completed admin protected incl. self-service deletion; unfinished accounts cannot be admin.
- (capability) CAP-5 Admin deletion: reuses trip outcome via automatic succession (manager then editor, addedAt then userId); self-service keeps explicit choices; opaque outcome fingerprint recheck.
- (capability) CAP-6 Admin password reset link: 1h single-use; preserves MFA; revokes sessions/trusted devices on completion.
- (capability) CAP-7 CLI recovery: trusted operator issues 1h link by username+base URL; browser sets password + verified replacement MFA atomically; replaces mfa-reset command; new MFA recovery codes.
- (capability) CAP-8 Activity: admin-visible event list with actor/type/date filters, pagination; failed sign-ins; routine edits batched (10 min); trip events minimal metadata; best-effort, never gates actions; no IP.
- (capability) CAP-9 Retention: 30/90/180/365 days default 90; shortening confirmed; opportunistic background cleanup, no scheduler.
- (capability) CAP-10 Overview: version, DB/storage health, user/admin/pending counts, trip/doc counts, storage bytes, recent admin actions and failed logins; per-metric freshness; Unavailable never zero.
- (capability) CAP-11 Account menu: Settings + Log out for all, Manage instance for admins; desktop sidebar control and mobile Profile tab.
- (constraint) Admin status grants no trip access; every admin read/action checks current DB authority; privileged deletion is narrow, not a bypass.
- (constraint) Credential tokens: >=256-bit random, hashed at rest, purpose-bound, URL shown once; same-purpose replacement and any reset/recovery completion invalidate outstanding ones.
- (constraint) No new infrastructure: existing app container, Postgres, storage adapter; no email; no unauthenticated web recovery bypass.
- (constraint) Project: UI targets >=44px, username-only sign-in (existing normalization), schema changes ship generated Drizzle migration, tests first.
- (constraint) Private-trip Activity metadata limited to actor/action/timestamp/trip ID (provisional in brainstorm, finalized by architecture AD-9).
- (decision) Non-goals: email integration/resend, diagnostic logs, suspension, quotas, backup integration, registration/upload-limit controls, offline recovery codes, temporary recovery mode, multi-account legacy selection, tamper-evident audit, live Activity feed.
- (decision) Adopted companions: UX EXPERIENCE.md, DESIGN.md, architecture spine. Deferred to feature specs: route/table names, event enum, response shapes, indexes, cleanup cadence.
