The Adapter Keystone

Packt's images and documents currently ride on Vercel Blob alone. This session designs the replacement: a storage layer that runs self-hosted, in any Docker container — the user's Synology NAS included, but with zero NAS-vendor lock-in — while staying open to S3-compatible providers later.

Technique · Sheet 1/4Morphological Analysis

Locking the parameters

Before choosing a backend, the session broke the problem into independent settings and locked one value into each — a configuration panel, not a single decision.

Starting condition: real file storage isn't implemented yet — today it's faked and stubbed. No storage abstraction exists either; the app almost certainly calls the Vercel Blob shape directly. Both are prerequisite blockers this design has to clear. User

Technique · Sheet 3/4TRIZ Contradiction

Simplicity vs. flexibility

Self-hosted simplicity was the priority; multi-backend support was only worth it if cheap — not a hard requirement. That reads as a trade-off, until the complexity gets moved.

Synthesis · Sheet 4/4Converged scope

One interface, two problems solved

The StorageAdapter interface is the single move that resolves both the real today-blocker and the future flexibility goal at once.
