- (constraint) documents.url and trips.coverImageUrl are opaque strings in Postgres consumed as-is via plain <img src> / <a href> (no next/image, no remotePatterns) - consumers never branch on backend today; isBlobUploadUrl()/isLocalUploadUrl() in local-upload.ts exist only to decide cleanup eligibility, not for rendering
- (constraint) current local stub writes into public/uploads (Next.js static serving, no app mediation) - this contradicts the brainstorm's proxy-through-app decision for the real local-filesystem adapter; the two are not the same code path
- (decision) (decision by user) DB stores a ready-to-render URL, not an opaque key: local adapter returns a proxy path (/api/storage/<key>-shaped), S3-compatible adapter returns its own URL shape. No separate key column - del() must parse the key back out of the stored url string itself.
- (decision) (decision by user) local-adapter proxy route enforces trip-scoped auth (requireUser + assertTripAccess) on every file read - closes the current no-auth-on-file gap. Resolves owning trip via the existing scope-prefix convention (trip-documents/<tripId>/..., event-documents/<eventId>/... -> resolve via event/reservation lookup, same pattern as getEventTripId/getReservationTripId already used on the write side).
- (decision) (decision by user) S3-compatible adapter's read/auth posture (proxied vs direct-URL) is explicitly Deferred - it is a Should-scope item not being built this round. The StorageAdapter port still requires every adapter to expose a read capability (so proxying stays possible later), but whether S3 actually gets proxied is decided when that adapter is built, not now.
- (decision) (decision by user) E2E retires UPLOAD_STUB entirely once StorageAdapter exists - E2E runs the real local-filesystem adapter with STORAGE_PROVIDER=local pointed at an E2E-scoped root dir, exercising the real code path instead of a parallel stub.
- (decision) (decision, confirmed by user) Paradigm: Strategy pattern behind a single StorageAdapter port - not full hexagonal/ports-and-adapters app-wide, scoped to this one subsystem, same weight as the existing DB-mapper-layer convention.
- (decision) (decision, confirmed by user) Ownership split: key NAMING (scope prefix + ownerId + uuid + ext) stays a domain concern in upload-policy.ts (unchanged). StorageAdapter only does bytes I/O on an opaque key: put(key, file): Promise<url>, del(url): Promise<void> (adapter parses its own key back out of the url it produced), read(key): Promise<ReadableStream> for the proxy route. Adapter never knows about trips/events/reservations.
- (decision) (decision, confirmed by user) Singleton resolution mirrors src/db/index.ts's globalThis.__pgClient hot-reload-survival pattern: getStorageAdapter() resolves once from STORAGE_PROVIDER env var and caches on globalThis, same convention as the DB client singleton.
- (decision) (decision, confirmed by user) Shared tripId resolver: the proxy route's auth check and the write-side actions both call one resolver (key/ownerId + scope -> tripId, direct for trip-cover/trip-document, via event/reservation lookup otherwise) instead of each duplicating getEventTripId/getReservationTripId-style lookups inline.
- (decision) (decision, confirmed by user) File placement: src/lib/storage/storage-adapter.ts (interface + getStorageAdapter()), src/lib/storage/local-filesystem-adapter.ts (default adapter, PUID/PGID + bind mount target), proxy route at src/app/api/storage/[...path]/route.ts. S3-compatible adapter file (src/lib/storage/s3-adapter.ts) deferred to when that Should-item is built.
- (assumption) [ASSUMPTION] Vercel Blob's continued production use is out of scope entirely, not migrated: brainstorm intent frames this as a prerequisite blocker before containerized/self-hosted deployment, and explicitly drops a Vercel Blob adapter (S3-compatible covers that need if ever wanted). Read as: production cuts over from Vercel hosting to self-hosted Docker as part of this change, so local-filesystem-adapter alone is sufficient Must-scope with no interim dual-backend period. - (convention) getStorageAdapter() validates required env vars lazily on first resolution per process (mirrors db client construction-time validation via postgres(process.env.DATABASE_URL!)), throwing a clear error naming the missing var rather than failing deep inside an unrelated put/del call.
