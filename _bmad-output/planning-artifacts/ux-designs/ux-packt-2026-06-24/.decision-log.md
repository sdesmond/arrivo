## Entry 1 — Working mode & warning color

## Entry 2 — Form factor & header layout

- Budget tab is responsive, same behavior as the other 6 trip-detail tabs — no desktop-only special-casing.
- Budget tab header treatment: **big number + progress bar**. Remaining (or Actual) shown as a large figure with a horizontal progress bar (Actual vs. Budget), bar color driven by threshold state (neutral/warning/danger). Rejected the equal-weight stat-card row — big number reads faster at a glance, matching PRD's "immediately knows whether on track" framing (§1 Vision).
- Big number leads with **Actual spent** ("$3,760 spent"), not Remaining — frames the header as a running total. Budget and Remaining shown smaller beneath, still in the same header block.

## Entry 3 — Category breakdown

- Category breakdown (FR-6) is a **tile grid**, not a list/table and not mini-bars-per-row (mini-bars were rejected as edging into chart territory the PRD explicitly defers to Phase 2, §7.2/§4.6). Each tile: category name centered above, subtotal as a big number inside the tile. Tiles sized to wrap several per row — at least 2 per row on mobile, more on wider viewports. Zero-item categories still omitted per FR-6.

## Entry 4 — Actions & status visibility

- "Add Misc Expense" (primary) and conditional "Recalculate Conversions" (secondary, only when at least one Cost Entry's currency differs from Trip Currency — per addendum) sit together in a toolbar row, between the header and the category tile grid. Rejected floating-action + overflow-menu — both actions are common enough on this tab to earn visible buttons.
- Threshold status (FR-11) shows as a **badge** (icon + word: "On track" / "Warning" / "Over budget") next to the big Actual number, in addition to the progress bar's color.
- New pattern: the **Budget tab label itself** gets the same Warning/Error icon (no icon at neutral, to avoid noise) so the status is visible without opening the tab. The trip detail tab bar (`page-client.tsx` TABS) currently renders plain text labels only — this is the first tab to carry a status icon, so `TripDetailTab`/`TABS` rendering needs a small icon-slot addition, not a new system.

## Entry 5 — Misc Expense modal field layout (visual reference)

- Spencer shared two inline reference screenshots (not saved as files — described here, no file path to log under `imports/`):
  1. A stacked set of full-width rounded "field card" rows: row 1 = currency-symbol dropdown ("$ ▾") + amount input on the same line; row 2 = a disclosure row ("Activities" + small red required-dot + chevron at the right, opens a category picker); row 3 = a labeled textarea row ("Add description" label, freeform text below).
  2. The currency-symbol dropdown opens an overlay list: each row = two-letter country/currency code swatch + full currency name + ISO code, checkmark on the currently-selected one. No search field needed — full scrollable list is fine even at ~150 currencies.
- **Decision:** TripAddExpenseModal (FR-7) adopts this stacked field-row pattern: currency+amount row, category disclosure row (red required-dot, no default selected per FR-7), date row, note/description row (textarea). Rejected mirroring the existing plain `CostDialog` layout for this new modal.
- **Resolved:** `CostDialog` (`src/components/packt/cost-dialog.tsx`) is restyled to the same field-row pattern as the new Misc Expense modal — one visual language for cost entry everywhere amount+currency+category appears (CostDialog and TripAddExpenseModal). `TripEditBudget`'s currency dropdown (addendum redesign) reuses the same currency-picker overlay (code swatch + name + ISO, checkmark, no search) for consistency across all three currency pickers in this feature.

## Entry 14 — Layout & headline figures

- New FRs surfaced during this discovery and added to the PRD: **FR-20 (Total Spend)** and **FR-21 (Average Trip Spend)** — Spencer assumed Total Spend was already in scope (it wasn't) and asked for Average Trip Spend alongside the already-specified Average Daily Spend (FR-18).
- Spending view layout, top to bottom: date filter (dropdown) → three headline figures (Total Spend, Average Trip Spend, Average Daily Spend) → category breakdown donut → budget adherence donut → spend-over-time bar chart → destination breakdown donut. (Spencer had no preference on the order of the last two; bar chart placed first since the headline figures above it reference the same total it visualizes.)
- Each chart sits on its own card for visual separation — Spencer's explicit request, since the page now has 4 charts and needs to read as 4 distinct units, not one undifferentiated block.
- Donut-with-centered-text pattern (per shadcn's "Pie Chart - Donut with Text" example, https://ui.shadcn.com/charts/pie#charts, referenced directly by Spencer): category and destination donuts center on total spend; budget adherence donut centers on trip count ("4 Trips" / "1 Trip", singular/plural handled).
- Legends sit beneath their chart (shadcn's default placement) — each chart's own card boundary is what keeps a legend from being misread as belonging to a neighboring chart, reinforcing the per-chart-card decision above.
- Filter control: dropdown (This Year / Last Year / Last 12 Months / All Time), not a segmented control like the existing Trips/Spending tab toggle — a deliberate visual distinction between the two-view tab switch and the within-view filter.
- Empty states: zero trips ever logged → "Add costs to your trips (reservations, events, misc) and track them over time here."; trips exist but none match the filtered range → "No trips in the selected range."

## Entry 16 — Accessibility review (WCAG 2.1 AA), Travel Retrospective

  5. (Note) Focus order across 4 stacked chart cards wasn't explicit if a legend becomes interactive — fixed: natural top-to-bottom order, interactive legends stay within their own card.
  6. (Note) `fg-4`'s reuse for the Unknown segment had no contrast check — folded into fix #2's contrast-requirement.
