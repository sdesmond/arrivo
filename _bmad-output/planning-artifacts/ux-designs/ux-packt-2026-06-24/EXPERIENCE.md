# Packt — Budget Tab & Travel Retrospective — Experience Spine

> Trip Budget Management & Travel Retrospective (PRD `prd-packt-2026-06-23`). Adds a Budget tab to the existing trip-detail view, redesigns the event/reservation cost dialog and `TripEditBudget`, adds a Settings → Preferences → Budget section, and adds a "Spending" view to the existing History page for cross-trip reporting. Paired with this run's `DESIGN.md`.

## Foundation

Responsive web, same behavior as every other trip-detail tab — no desktop-only special-casing. Next.js App Router + shadcn/ui + Base UI on Tailwind v4, inheriting Packt's existing CSS-custom-property token system (`src/app/globals.css`). `DESIGN.md` is the visual identity reference for this feature's new tokens (warning color, status badge, category tile, field-row, currency-picker-row); this spine is the behavioral contract. Single-tenant per trip; access roles (`viewer < editor < owner`) gate every write per the existing pattern.

## Interaction Primitives

- Mouse/touch primary, same as the rest of the trip-detail surface — no new keyboard-shortcut layer introduced for Budget specifically.
- Misc Expense modal and the redesigned `CostDialog` are fully keyboard-operable end to end: tab order is amount → currency → category → date → note → save/cancel (PRD §4.4 FR-8 feature-specific NFR), consistent with the existing cost-entry dialog's keyboard operability.
- Currency picker overlay: arrow-key/scroll to browse, `Enter` or click to select, `Esc` to dismiss without changing the current selection. Selecting a currency or pressing `Esc` always closes the overlay and returns focus to the currency trigger it was opened from — Tab order resumes from there, never from inside the dismissed overlay.
- Category disclosure row opens the category picker on click/`Enter`; selecting a category, or pressing `Esc`, closes the picker and returns focus to the disclosure row — same return-focus guarantee as the currency picker.
- "Recalculate Conversions" and "Add Misc Expense" are standard button activations (click/`Enter`/`Space`) — no confirmation step for either beyond the Misc Expense modal's own save action.
- Spending view date filter is a standard dropdown (click/`Enter`/`Space` to open, arrow keys to browse, `Enter` to select, `Esc` to dismiss without changing the current selection) — no custom keyboard layer.
- Donut chart elements are not independently focusable beyond what the underlying chart library provides by default — chart data is also available via the figures/legend text, never chart-interaction-only.

**Banned:** auto-refreshing conversion rates in the background (PRD §6 Non-Goals — one-time conversion at entry only, refreshed solely via explicit Recalculate, a Trip Currency change, or a profile currency change); charts on the per-trip Budget tab (charts live exclusively in Travel Retrospective's Spending view); a color-only legend or segment treatment on any Travel Retrospective chart (labels/legend text are the primary signal, color is secondary).

## Accessibility Floor

Behavioral. Visual contrast lives in `DESIGN.md`.

- WCAG 2.1 AA, color-blind-safe: every warning/danger state (status badge, progress-bar fill, tab icon) pairs its color with a distinct icon (Warning / Error) — color is never the sole signal (PRD §5 Cross-Cutting NFRs).
- Misc Expense modal and `CostDialog` are fully keyboard-operable with no mouse-only interaction (PRD §4.4 FR-8 NFR) — tab order matches visual order (amount, currency, category, date, note, save/cancel).
- Currency picker overlay and category disclosure picker are both keyboard-dismissable (`Esc`) without committing a change.
- Status badge and tab status icon both carry an accessible label/text alternative (not icon-only with no text equivalent) so screen readers announce the state, not just an icon glyph — see the Tab status icon row in Component Patterns for the exact DOM/ARIA shape.
- Threshold validation errors (Settings) are announced inline next to the relevant input, not only via toast.
- Category is required on both the Misc Expense modal and `CostDialog` with no visible persistent marker (no dot/asterisk) — the underlying control still carries `aria-required="true"`, and the requirement is surfaced to all users via an inline validation message if save is attempted with no category chosen.
- Every Travel Retrospective donut leans on direct segment labels or a legend with text as the primary signal — color (including the category palette's 11 steps and the budget-adherence under/on/over colors) is never the sole way to distinguish a segment, extending the same color-blind-safe floor from threshold states to chart form (PRD §5).
- Each chart's data is also exposed as text (segment labels, legend, or the headline figures above it) — never chart-visualization-only, so the same information is available to a screen reader or a user who can't perceive the chart's color/shape distinctions.
- Donut center text (the "donut with text" figure) is a true text node, not an image or canvas-rendered label — readable by assistive tech like any other figure.
- Each of the 3 charts' root graphic element carries `role="img"` and an `aria-label` summarizing its data (e.g. "Category breakdown donut chart: Lodging $1,200, Food $640...") — the chart graphic has its own accessible name independent of any on-screen legend/label text (DESIGN.md `donut-chart.accessible-name`).
- The category palette's 11 hues and the "Unknown" segment's `fg-4` fill must each clear 3:1 non-text contrast (WCAG 1.4.11) against the chart-card surface and against any segment they can sit adjacent to — verified at implementation time per DESIGN.md's `contrast-requirement` notes, since exact hues aren't fixed in this spine.
- Changing the date filter announces the update to assistive tech via a polite live region (e.g. "Showing All Time — 12 trips") — the visual reshape of 3 charts + 3 figures happening at once would otherwise be silent for a screen reader user.
- The 3 chart cards follow natural top-to-bottom DOM/visual order, same as their Component Patterns sequence — no custom tab order. If a chart library's legend becomes independently interactive (e.g. clickable to toggle a segment), it stays within its own card's natural tab sequence, never jumping ahead of the next chart card.

## Key Flows

### Flow 1 — Sally tracks actual spend against her trip budget (PRD UJ-1)

1. Sally opens the trip detail view for a multi-day international trip she's planning. She set a budget total and currency when she created the trip.
2. As she adds events and reservations, the cost-entry dialog on each now also asks for currency and category — same `field-row` layout as the Misc Expense modal, currency defaulting to her Trip Currency.
3. She opens the Budget tab: the header shows "$2,140 spent" with a thin teal progress bar and "$1,860 remaining" beneath — neutral state, no badge yet. Below, category tiles show Lodging, Transport, Food with their subtotals.
4. She incurs a visa fee that isn't tied to any event. She taps "Add Misc Expense," fills the amount+currency row, picks "Misc" in the category disclosure row, leaves the date at today, and saves.
5. **Climax:** The modal closes and the Budget tab updates immediately — Actual ticks up to "$2,340 spent," a new "Misc" tile appears in the category grid, and because this crossed her 80% warning threshold, a Warning badge appears next to the Actual figure and the progress bar turns amber. She didn't have to do any math — the tab told her.
6. She glances at the trip's tab bar later in the session: the "Budget" tab label itself now carries the same warning icon, so she sees the state without re-opening the tab.

Failure: the visa fee was entered in a foreign currency and the conversion lookup fails at save time → toast: "Couldn't convert currency — try again." The expense is not saved partially; she retries once her connection recovers.

### Flow 2 — Spencer changes Trip Currency mid-trip

1. Spencer is editing a trip whose Trip Currency is USD; he's already logged a hotel cost in EUR (converted to USD at entry) and a Misc Expense in USD.
2. He opens the Trip edit sheet and changes the currency dropdown to EUR.
3. The USD Misc Expense's currency no longer matches the new Trip Currency, so the system shows the confirmation dialog: "Some of your expenses don't match your new currency selection. Do you want to convert them to this new currency?" — Cancel / Leave As Is / Convert.
4. **Climax:** He picks "Convert." The dialog closes, the same recalculation routine used by the Budget tab's standalone Recalculate Conversions action re-fetches rates for the mismatched entry, and `TripEditBudget`'s read-only summary updates to reflect EUR totals immediately — no separate trip to the Budget tab required to see it take effect.

Failure: he instead picks "Leave As Is" — the currency changes but the USD entry's converted amount is left stale until he runs Recalculate later from the Budget tab; the Recalculate Conversions button becomes visible there as soon as he lands on it, since now at least one entry mismatches.

### Flow 3 — Spencer reviews his spending history across trips (PRD UJ-2)

1. Spencer has logged several real trips with budget and expense data. He opens the History page and switches from "Trips" to the new "Spending" view.
2. The view loads with the date filter defaulted to "This Year": three headline figures (Total Spend, Average Trip Spend, Average Daily Spend), then three chart cards — category breakdown donut, budget adherence donut, destination breakdown donut, each centered on its own figure (category and destination donuts center on total spend; budget adherence centers on trip count).
3. He opens the date filter dropdown and switches to "All Time."
4. **Climax:** Every figure and chart reshapes at once — the headline numbers update, the category donut's center figure changes, and the budget adherence donut's trip count grows from "4 Trips" to "12 Trips" as more trips enter scope. No per-trip digging required — one filter, everything recomputes together.
5. He notices one of his trips never had a destination set — its spend shows up under a gray "Unknown" segment on the destination donut rather than vanishing from the chart.

Failure: Spencer opens the Spending view for the first time, before logging any trip spend at all — the view shows "Add costs to your trips (reservations, events, misc) and track them over time here." instead of empty charts.
