# Accessibility Review — Packt Location-Aware Itinerary

## Overall verdict

The spine gets the headline structural risk right: the Next Event row's two-zone restructure is explicitly reasoned through (nesting hazard, 44px minimum, DOM sibling order), and Schedule Conflict indicators correctly commit to icon+text over color-alone. But the same rigor applied to the Next Event row is not applied consistently to the Address pill's parallel restructuring, several sizing/state gaps exist (segmented-control widths, denied-permission dead-ends, live-updating content), and the Map Tab handoff — while correctly deferring the map library choice — under-specifies what accessibility contract that future library must satisfy. None of these are showstoppers for a draft spine, but several should be closed before this becomes an implementation-ready story.

## Findings

- **high** Address pill's own tap target size is unaddressed once FR-13 changes its behavior. `DESIGN.md` specifies `min-target: 44px × 44px` for the new `address-pill-edit-affordance` (pencil) but says nothing about the pill body itself, which becomes a *new* "open External Maps" action under FR-13. The current implementation (`place-row-action-bar.tsx:65-78`, `py-0.5` padding, ~24px effective height) sits well under 44px, matching Time/Cost chips. Because FR-13 redefines what tapping the filled pill *does*, it is a changed interactive control and falls under the project's 44×44px non-negotiable, not a grandfathered legacy element. (DESIGN.md § `address-pill-edit-affordance`; EXPERIENCE.md § Component Patterns, "Address pill (state-flip)"). _Fix:_ Add an explicit `min-target: 44px × 44px` line for the Address pill body itself in `DESIGN.md`, and note in EXPERIENCE.md that the filled-state pill needs its own hit-area/padding increase independent of its visual chip size (e.g. an invisible padded wrapper), matching the treatment already given to the Next Event row.

- **high** Address pill restructuring has the same nesting/DOM hazard as the Next Event row, but it isn't named as such. Today `place-row-action-bar.tsx:65-78` renders the location affordance as a single `<button onClick={onOpenLocation}>` wrapping both icon and label. Adding an independently-tappable trailing pencil (EXPERIENCE.md line 84: "Tap filled Address pill body... Tap the trailing pencil...") requires splitting that single button into two sibling interactive elements — structurally identical to the Next Event row problem the decision log spent a full paragraph resolving (`.decision-log.md` line 23). The spine states the *interaction* ("two adjacent, independently reachable targets") but never states the *DOM fix* the way it does for the Next Event row ("never nested inside the row's outer Link"). (EXPERIENCE.md § Interaction Primitives, § Component Patterns "Address pill (state-flip)"). _Fix:_ Add one sentence mirroring the Next Event row language: "The pill body and pencil affordance are DOM siblings inside a shared non-interactive container — the pencil is never nested inside the pill's `<button>`."

- **medium** Denied/blocked geolocation permission has no distinct accessible state. EXPERIENCE.md (Component Patterns "Geo-hint pill"; State Patterns "Next Event located, geolocation missing/denied") treats "missing" and "denied" as one state with one label ("Enable location for directions"). Browsers permanently suppress the native permission prompt after an explicit deny — a second tap is a silent no-op with no prompt and no feedback, which is worse for screen-reader/switch users than sighted users who might notice nothing happened. (EXPERIENCE.md § Component Patterns, § State Patterns). _Fix:_ Add a third state distinguishing "not yet asked" (tap triggers native prompt) from "previously denied" (tap re-attempts, and if still blocked, pill label/aria-live region communicates "Location blocked — enable it in your browser settings" instead of repeating the same call-to-action indefinitely).

- **medium** Live-updating content has no aria-live guidance. The Distance/Time pill text and the Schedule Conflict row/day badges can change value or appear/disappear without a full page navigation (Flow 3 resolution: "clears the conflict on next render" after an in-dialog time/order/mode edit; distance/time is inherently a moving target as the PRD's "live distance" framing implies). Concern 6 in this review's brief and WCAG 4.1.3 both point at this. Nothing in EXPERIENCE.md's Accessibility Floor or State Patterns sections specifies whether these regions are `aria-live="polite"`, `aria-live="off"`, or how update frequency is bounded for screen readers (a rapidly re-announcing "12 min walk" → "11 min walk" would be noisy). (EXPERIENCE.md § Accessibility Floor, § State Patterns). _Fix:_ Add a line to Accessibility Floor: distance/time text updates are not wrapped in an assertive live region (avoid announcement spam); Schedule Conflict badge appearance/disappearance after an in-page edit uses `aria-live="polite"` so the change is discoverable without a full re-scan.

- **medium** Getting Around segmented control and Map Tab day selector specify height but not width/keyboard-navigation model. `DESIGN.md` gives `each-segment-min-target: 44px height` for both (lines 56, 71) but no width guarantee — a 4-segment icon+label group or a horizontally-scrollable day selector with many days risks segments narrower than 44px, which still fails WCAG 2.5.8 (both dimensions must clear 44px, not just height). Neither EXPERIENCE.md's Interaction Primitives nor Accessibility Floor states the keyboard interaction model (arrow-key roving tabindex typical of segmented/tab controls, vs. plain Tab-through buttons), which matters once there's a scrollable day selector that could have 10+ segments. (DESIGN.md § `getting-around-segmented-control`, § `map-tab-day-selector`; EXPERIENCE.md § Interaction Primitives). _Fix:_ Add explicit minimum width (or `min-target: 44px × 44px` matching the pill convention) for each segment, and state the keyboard model (e.g. "arrow-key navigation within the group, Home/End to jump to first/last segment, matching the existing trip-detail tab bar's keyboard behavior" — or explicitly "plain Tab order" if that's the intended simpler model).

- **medium** Map Tab spine hands off pin accessible-naming correctly but is silent on map keyboard/non-visual operability and no text-list fallback is required. EXPERIENCE.md line 97 correctly defers pin labeling to "once the interactive map dependency is chosen," which is the right call given the PRD explicitly declines to prescribe the library (PRD §6.2, §13.1 Q3). But the spine should still hand off, as a requirement independent of library choice: (a) keyboard operability of pan/zoom/pin-focus (WCAG 2.1.1), (b) a non-map fallback — e.g. the itinerary's existing list of Located Items already satisfies "don't make map features the only way to understand the itinerary" per PRD §8, but the spine doesn't say the Map Tab itself must expose that list/alternative for users who cannot operate a drag-based map, and (c) respecting `prefers-reduced-motion` for pan/zoom/fly-to animations. Only pin accessible-naming is called out; the other three are silently absent. (EXPERIENCE.md § Accessibility Floor, § Component Patterns "Map Tab"). _Fix:_ Extend the line-97 handoff into a short bulleted sub-list: pins need accessible names/labels (existing text) **+** map viewport must be keyboard-operable or provide an equivalent list-based control **+** motion respects `prefers-reduced-motion` **+** color contrast of the single `accent-brand` pin must be verified against whichever base map style architecture selects (satellite vs. street tiles could fail contrast differently).

- **low** Distance/Time pill and geo-hint pill's mutual-exclusivity relies on identical slot position, but focus order after a state transition (e.g. permission granted mid-session, pill swaps from geo-hint to distance/time) isn't addressed. If the pill is focused when its underlying state changes (permission granted while focus is still on it), does focus remain on the same DOM node with updated content, or does the node get remounted (losing focus)? EXPERIENCE.md's Interaction Primitives states "never both behaviors on the same tap" (behavioral) but not focus continuity across the swap. (EXPERIENCE.md § Interaction Primitives; § State Patterns). _Fix:_ Add one sentence: "The pill is a single stable DOM node across the geo-hint ↔ distance/time transition — focus is preserved, only content/label updates."

- **low** Schedule Conflict day badge accessible name isn't spelled out the way the row icon's is. DESIGN.md/EXPERIENCE.md give the row icon a concrete accessible-name example ("Time, Schedule conflict" via visually-hidden span, mirroring `TabStatusIcon`). The day-level badge ("1 tight connection today") is given as voice/tone copy but not tied to the same icon+`sr-only` pattern explicitly — it's implied by "reuses status-badge pattern" but not stated as directly as the row icon was. (DESIGN.md § `schedule-conflict-day-badge`; EXPERIENCE.md § Voice and Tone). _Fix:_ Add one line confirming the day badge's icon is `aria-hidden` with the count text as the visible+accessible name (no separate visually-hidden span needed here since the count text itself is meaningful, unlike the bare triangle-alert row icon).

## What's already solid

- The Next Event row two-zone restructure is the standout piece of this spine: it correctly diagnoses the nesting/44px conflict, resolves it as sibling DOM nodes, and explicitly preserves the existing Link's accessible name and tab order (EXPERIENCE.md § Accessibility Floor, § Component Patterns).
- Schedule Conflict indicators commit to icon+text everywhere, explicitly reusing the `TabStatusIcon` `aria-hidden` + `sr-only` pattern already proven in the budget feature — verified against the actual `tab-status-icon.tsx` implementation and it matches.
- Geolocation permission flow (FR-2) is handled well at the behavioral level: strictly user-initiated via tap, never auto-prompted on load, and denial doesn't produce repeated blocking prompts — directly satisfies PRD SM-C2 and the Cross-Cutting Privacy NFR.
- Freeform-item silence (no placeholder, no nudge, no warning) is enforced consistently across every surface in State Patterns and Flow 2 — a real accessibility/cognitive-load win, not just a visual one.
- Distance/Time and geo-hint pills get concrete accessible-name examples that don't rely on adjacent row context ("Open directions to {event name}, 12 minutes"), correctly anticipating that the pill is now a sibling rather than nested content.
- Map pin color-coding is deliberately rejected in favor of the day selector doing the scoping work — avoids a qualitative color scale that would need redundant non-color encoding for N days.
