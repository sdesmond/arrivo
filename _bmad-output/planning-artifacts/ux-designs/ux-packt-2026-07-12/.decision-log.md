Only the Next Event row changes shape; the "Now" row and Linked-event row are unaffected (FR-1/FR-3 scope to Next Event only — "Now" means you're already there).
- **Getting Around control:** Segmented control (icon+label, walk/drive/transit/smart), not a radio list.
- **Address pill state-flip:** Pill tap opens External Maps when filled; a secondary edit affordance (pencil/chevron) sits at the pill's trailing edge, both visible at once — no overflow menu.
- **Day Route Strip origin:** Fresh new component, not a restyle of `mini-map-rail.tsx`/`RailPanel` — those are dead-end mockup code per addendum; only borrow the general "route preview card" idea if useful, not the structure.
- **Map Tab day selector:** Segmented/tab control (Whole Trip + one segment per day, horizontally scrollable), same visual weight as the trip-detail tab bar — not a dropdown.
- **Row-level Schedule Conflict indicator:** Inline warning-triangle icon appended next to the Time chip on the affected `PlaceRow`, mirroring the existing `TabStatusIcon` convention (icon + visually-hidden text for accessible name, e.g. "Time, Schedule conflict").
- **Geolocation compact hint (FR-2):** Occupies the same slot the Distance/Time pill would use on the Next Event row — a same-size pill reading "Enable location for directions" that triggers the browser permission prompt on tap. No separate banner.
- Because this feature inherits the existing token system almost entirely (schedule-conflict reuses budget's warning/danger, no new brand colors needed), DESIGN.md for this pass is expected to be components-only (like the June budget DESIGN.md), not a new palette — skipping color-theme/design-direction creative tools; wireframes/mocks deferred to Finalize's key-screen step.
- **Map pins:** Single `--accent-brand` color for all pins, no per-day color-coding — day filtering (via the Map Tab day selector) does the separation work instead of a qualitative color scale.
- **Day Route Strip thumbnail:** Clickable from day one, deep-links to Map Tab scoped to that day (FR-16 pulled forward since both surfaces ship in this same UX pass — no throwaway non-interactive state).
- **Navigation icon:** lucide `Navigation` icon for "opens external maps" affordances (Next Event distance pill, Address pill's filled/open-maps state) — distinct from `MapPin`, which stays reserved for "has a saved location."
- **Key Flows:** Reuse PRD UJ-1–UJ-4 verbatim (Maya/Tokyo navigation, Jordan/freeform day, Priya/schedule conflict, Luis/whole-trip map) as EXPERIENCE.md Key Flows — already have named protagonists, entry state, path, climax, resolution, edge case.

## Late change: Address pill → real shadcn ButtonGroup

Mid-editorial-pass, user asked (referencing ui.shadcn.com/docs/components/base/button-group) for the filled Address control to look like/be an actual shadcn Base UI ButtonGroup — text segment on the left, icon segment on the right — rather than the two-separate-floating-pills-with-a-gap treatment the accessibility review had pushed toward. Scope confirmed: Address pill only, not the Now Card's Distance/Time pill or geo-hint pill (those stay single buttons with their existing icon-leading layout).

- **Resolved:** Filled Address control is now a genuine 2-segment `ButtonGroup` — segment 1 (`outline` variant, map-pin icon + location name) opens External Maps; segment 2 (`outline` variant, pencil icon-only) opens the edit dialog. Both `outline`-variant, sharing a border per shadcn's own guidance ("outline buttons don't need a `ButtonGroupSeparator`, they have a border") — no visible gap, genuinely joined. Empty state is unaffected: still a single button.
- This is a strictly better answer to the accessibility review's high-severity nesting/sizing findings than the earlier ad hoc "shared non-interactive wrapper" — a real ButtonGroup is a semantic HTML/ARIA primitive built exactly for this "grouped-but-independent" pattern, native `role="group"` semantics included.
- DESIGN.md's `address-pill` + `address-pill-edit-affordance` tokens merged into one `address-button-group` token with `segment-1`/`segment-2` sub-fields. EXPERIENCE.md's Component Patterns, Interaction Primitives, Accessibility Floor, and State Patterns rows updated to describe ButtonGroup segments instead of "pill body" + "trailing pencil." `mockups/address-pill.html` state (C) rebuilt to render actual joined outline buttons instead of two dashed-outline pills with a gap.
- Also answered inline (no spine change needed): the "Smart" Getting Around option is inferred/auto transit-mode selection from trip context (PRD FR-6/FR-7); the inference logic itself is optional for MVP and falls back to the same deterministic default as "no explicit override," so shipping "Smart" as a selectable segment doesn't require the inference to exist yet — it just reserves the slot per FR-8.
