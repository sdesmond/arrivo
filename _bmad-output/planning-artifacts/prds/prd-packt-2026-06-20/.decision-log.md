## 2026-06-21 — Reconciliation against offline-storage UX pass (`ux-packt-2026-06-20`)

- **Change signal:** `bmad-ux` Finalize for the offline-storage feature surfaced three deviations from this PRD (logged in `EXPERIENCE.md`'s "PRD Deviations Carried Forward" and that workspace's `.decision-log.md`, both dated 2026-06-21) plus resolutions for both Open Questions. Reconciled into `prd.md` + `addendum.md` as follows:
  - **FR2 / Glossary "Entity tier" narrowed.** Documents move from review-merge to last-write-wins (silent auto-merge), matching packing list — full diff/merge UI for documents was judged too costly to show meaningfully, and Packt already permits duplicate document names, which removes most of what would otherwise look like a naming conflict. One exception carved out to hold NFR1's no-silent-discard line: a document *deletion* conflict still prompt-merges, folded into the same conflict review screen (FR8) as a tagged row rather than a separate screen.
  - **FR6 / addendum Smart Pin section narrowed to global-only.** Per-trip opt-out granularity removed from FR6; one global Smart Pin configuration (Preferences tab) applies to every trip. `offline_settings` table description in addendum.md updated from `trip_id`-keyed to user-scoped.
  - **FR12 (offline search) descoped, moved to Out of Scope.** User chose "move to Out of Scope" over deleting outright or marking deferred-inline, to keep a paper trail without implying it's still an active FR. Direction noted: search gets built into trip list/travel history as plain client-side filtering, treated as a separate future initiative, not an offline-specific capability.
  - **OQ1 resolved and removed.** UX pass specified the failure UX: TripCover gets a persistent `CloudAlert` state + interrupting toast naming the reason ("Not enough storage to pin this trip") with Retry/dismiss; FR13's existing rollback guarantee already settled all-or-nothing vs. partial pin. No PRD-body change needed beyond closing the question — the UX detail lives in `EXPERIENCE.md`, not the PRD.
  - **OQ2 resolved and removed.** Decided not to add a pre-pin size warning — OQ1's failure-path backstop (CloudAlert + toast + Retry) already covers the rare case where a trip doesn't fit, so a second "this might be large" warning would duplicate it. Open Questions section removed from `prd.md` entirely now that both OQ1 and OQ2 are closed (matches the precedent set when the original Smart Pin OQ1 resolved into FR6 during initial Finalize — closed OQs are removed from the PRD body, not retained as a "resolved" list; the resolution narrative lives here).
